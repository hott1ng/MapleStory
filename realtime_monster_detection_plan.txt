实时识别游戏进程中怪物位置方案

目标：

实时获取游戏窗口画面，使用 YOLO 模型识别怪物，并输出怪物在游戏窗口内的位置坐标。


一、整体流程

游戏窗口截图
  -> YOLO 模型识别
  -> 得到怪物检测框 bbox
  -> 计算怪物中心点坐标
  -> 输出、显示或提供给后续逻辑使用


二、实时画面来源

实时识别时不要每秒保存图片到硬盘。

推荐方式：

直接从游戏窗口截图到内存，然后立刻送入 YOLO 推理。

不推荐方式：

截图 -> 保存 png -> 再读取 png -> 识别

原因：

磁盘读写会增加延迟，影响实时识别速度。

初期目标帧率建议：

2-5 FPS

流程稳定后再尝试提高帧率。


三、模型选择

继续使用当前训练出的模型：

D:\MapleStory\runs\detect\runs\maplestory_detect\weights\best.pt

当前模型只用少量图片训练，适合验证流程，不适合稳定实战。

后续建议继续补充标注数据：

怪物至少 100-300 张图片。

标注数据应覆盖：

1. 不同地图
2. 不同怪物位置
3. 不同遮挡情况
4. 不同背景
5. 不同怪物姿态

如果只需要识别怪物，类别只保留：

0: monster

不要标注角色，除非后续也需要识别角色位置。


四、识别输出内容

YOLO 每次识别会返回每个怪物的检测框：

x1, y1, x2, y2, conf, class

其中：

x1, y1 是左上角坐标
x2, y2 是右下角坐标
conf 是置信度
class 是类别

实际需要的怪物中心点坐标：

center_x = (x1 + x2) / 2
center_y = (y1 + y2) / 2

输出示例：

monster_count: 3

monster 1:
  center: 312, 455
  confidence: 0.82

monster 2:
  center: 670, 430
  confidence: 0.76


五、坐标系统

推荐统一使用窗口内坐标：

窗口左上角 = 0,0

这样无论游戏窗口移动到屏幕哪里，怪物坐标都稳定。

如果后续需要转换为屏幕坐标：

screen_x = window_left + center_x
screen_y = window_top + center_y


六、实时显示方式

第一阶段建议做调试显示窗口。

调试窗口显示内容：

1. 当前游戏截图
2. 怪物检测框
3. 置信度
4. 怪物中心点

这样可以直观看到识别是否准确。

稳定后可以改成只输出坐标，不显示画面。


七、性能建议

当前环境使用 CPU，实时识别不建议一开始追求高 FPS。

推荐初始参数：

模型：yolo11n
imgsz: 640 或 512
conf: 0.25
device: cpu
FPS: 2-5

如果画面卡顿：

1. 降低 imgsz，例如 416
2. 提高 conf，例如 0.3
3. 降低识别频率，例如 2 FPS

如果有 NVIDIA 显卡，可以考虑使用 GPU：

device=0


八、推荐落地顺序

第一步：

继续补充怪物标注数据，至少先做到 50 张。

第二步：

重新整理数据集，确认 data.yaml 中类别为：

names:
  0: monster

第三步：

重新训练 YOLO 模型。

第四步：

编写实时识别脚本：

1. 输入或选择游戏窗口名
2. 根据窗口标题找到窗口句柄
3. 从窗口内存截图
4. 使用 YOLO 模型推理
5. 得到怪物 bbox
6. 计算怪物中心点
7. 显示画框
8. 控制台打印坐标

第五步：

根据识别效果调整 conf、imgsz 和训练数据。


九、最小可行目标

先实现以下效果：

双击程序
输入游戏窗口名
实时显示识别画面
怪物身上有框
控制台打印怪物中心坐标

示例输出：

monster_count: 2
monster 1 center=(320, 450), conf=0.83
monster 2 center=(690, 430), conf=0.78


十、后续增强方向

1. 自动保存识别日志
2. 只识别游戏画面区域，排除 UI 区域
3. 加入小地图或角色位置识别
4. 区分不同怪物类别
5. 增加检测框稳定逻辑，减少闪烁
6. 加入简单目标追踪，避免每帧目标编号变化
